# Feature Task Activity

Keep this file as the engineer-readable broader view of feature development.
Task files remain the source of detail.

Organize this file freely. Use prose, lists, links, tables, or headings only
when they help express sequencing, priorities, progress, dependencies, or
broader feature-development intent. Broad implementation plans produced by
`../../skills/plan-feature-work/SKILL.md` belong directly in this file.

Broad plans may include intended implementation stack, platform capabilities,
libraries, infrastructure, and other technical direction when those details
materially affect feasibility, candidate-slice boundaries, dependencies,
ordering, risk, or verification. Label each material technical detail as one of:

- established in the current project;
- approved by the engineer for the plan;
- a provisional planning assumption;
- an unresolved decision.

State the planning consequence. For example, a framework-provided capability
may remove a supporting slice, while a missing required capability may create
one.

Candidate slices in a broad plan are provisional planning units, not formal
tasks. Formal tasks remain separate directories created through
`../../skills/create-task/SKILL.md`.

This file may summarize planning-relevant technical direction, but it does not
replace canonical project configuration, `AGENTS.md`, or an appropriate
architecture decision record for durable adopted choices.

Do not impose fixed lifecycle sections.
