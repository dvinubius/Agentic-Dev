# Implemented Application Behavior

Document behavior that exists in the current system.

Organize files by user workflow, subsystem, API, operator concern, or another
project-appropriate boundary.

Each document should make clear:

- the behavior or contract described;
- important inputs, outputs, states, and failure modes;
- relevant configuration or permissions;
- links to related specs when useful;
- whether any content is historical, proposed, or incomplete.

Do not document unimplemented specs as though they already work.
